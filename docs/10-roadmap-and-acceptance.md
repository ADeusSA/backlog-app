### Итерация 2 — глубина
Журнал сессий + `playtime_mode = sessions`; несколько прохождений; heatmap и стрики; итоги года (страница + экспорт PNG); экспорт списка в Markdown; редактирование горячих клавиш; трей и запуск свёрнутым; активация достижений на основе сессий (стрик, сова); светлая тема. **Итерация закрыта** (ADR 0008, 0009).

### Итерация 3 — внешние данные
Импорт из IGDB/Steam/SteamGridDB/Wikidata (08); импорт библиотеки Steam с часами; «Обновить из источника»; настройки провайдеров и приоритетов полей.

## 2. Нефункциональные требования

| Область | Требование |
|---|---|
| Переносимость | Приложение работает из любой папки без установки; данные по умолчанию в `<exe>/data`; нет записи в реестр (кроме того, что делает сама ОС для WebView2); при переносе папки на другой ПК всё продолжает работать |
| Производительность | Холодный старт до интерактивного UI ≤ 2.5 с на SSD; открытие любой страницы ≤ 200 мс на базе из 2 000 игр и 4 000 изображений; скролл сетки 60 fps; потребление памяти в покое ≤ 350 МБ |
| Надёжность | Любая запись — транзакция; аварийное завершение не портит базу (WAL); автобэкап перед миграцией и раз в день; синхронизация никогда не затирает более новые данные без подтверждения |
| Безопасность | Токены только в защищённом хранилище ОС; WebView не имеет прямого доступа к ФС/сети, только через IPC с проверкой аргументов; внешние ссылки открываются в системном браузере; CSP без `unsafe-eval` |
| Доступность | Полная клавиатурная навигация; видимый фокус; контраст ≥ 4.5:1; reduced-motion |
| Локализация | ru (основной), en; все строки во словаре; форматирование через `Intl` |
| Совместимость | Windows 10 21H2+ и Windows 11 x64, WebView2 Evergreen; масштаб 100–200 % |
| Размер | Portable zip ≤ 250 МБ, распакованная папка ≤ 400 МБ (Electron 44); данные пользователя отдельно в `data/` |
| Журналирование | `logs/app.log` с ротацией; уровни; без персональных данных и токенов |

## 3. Правила для моделей-исполнителей

1. **Источник истины — эти документы.** При противоречии: постановка пользователя (в этом чате) → 00-TZ → тематический документ → референс HTML. Отклонение от ТЗ требует записи в `docs/decisions/NNNN-*.md` (ADR: контекст, решение, последствия).
2. **Порядок реализации** — по блокам §1 сверху вниз; каждый блок завершается работающим приложением (можно запустить и покликать), а не «слоем».
3. **Каждая задача = вертикальный срез**: миграция/запрос → сервис → IPC-команда → UI → тест. Никаких «сначала весь backend».
4. **Тесты**: юнит-тесты на сервисы и билдер фильтров (Vitest), интеграционные на репозитории с реальной SQLite in-memory, e2e-смоук на критические сценарии (создать игру → сменить статус → появилась в «Играю» → кольцо изменилось). Покрытие сервисного слоя ≥ 80 %.
5. **Код**: TypeScript strict; ESLint + Prettier из репозитория; именование файлов kebab-case; React-компоненты — function components + hooks; состояние сервера — TanStack Query, локальное UI-состояние — Zustand; формы — react-hook-form + zod (схемы zod — единый источник валидации для UI и IPC).
6. **Дизайн**: только токены из `tokens.css`; анимации только из `motion.ts`; новый компонент — сначала в Storybook-подобной странице `/dev/ui` (доступна в dev-сборке) в всех состояниях.
7. **Коммиты**: Conventional Commits (`feat(library): …`), небольшие; ветка на блок.
8. **Definition of Done для блока**: критерии приёмки документа выполнены; нет ошибок в консоли; проверено при 100 % и 150 % масштабе; проверено с пустой базой и с демо-базой (200+ игр); reduced-motion проверен; строки локализованы; изменения задокументированы (если меняют ТЗ — ADR).
9. **Запрещено**: запросы в интернет из renderer; хранение секретов в БД/настройках/логах; блокирующие операции в UI-потоке (конвертация изображений — в backend/worker); `any` в публичных типах; inline-стили с цветами.

## 5. Решения по открытым вопросам (приняты пользователем 2026-09-07)

| Вопрос | Решение | Документ |
|---|---|---|
| OAuth и Google Cloud | Один OAuth-клиент владельца сборки, вшит в приложение, проект опубликован (production) с non-sensitive scope `drive.file`. Конечный пользователь видит только кнопку «Войти через Google»; приложение можно передать другому человеку без настроек. Пошаговая одноразовая настройка — 03 §11 | 03, 05 §8 |
| Светлая тема в итерации 1 | Нет, только тёмная Aurora | 04 §8 |
| Шкала оценок | 1–10, показ как 5 звёзд с половинками | 02, 06 §6.2 |
| Статус «Поиграл» | Да | 02 |
| Демо-данные при первом запуске | Опциональный чекбокс в мастере | 05 §8 |
| Достижения и уровни | В итерации 1 (кроме зависящих от журнала сессий) | 09 |
| «Пиратка» | Это значение владения (`ownership = pirated`), а не платформа; платформы остаются PC / PS / Xbox / … | 02 §3.8, 06 §6.2, 07 §7 |

Новых открытых вопросов нет; дальнейшие уточнения исполнители оформляют как ADR в `docs/decisions/`.
