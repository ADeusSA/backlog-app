# ADR 0007 · Импорт из внешних источников: что сделано и чем отличается от документа 08

Дата: 2026-09-08. Статус: принято. Дополнено 2026-09-08 (RAWG, язык данных).

## Контекст

Пользователь попросил: при добавлении игры получать данные «из Steam или SteamDB» по названию
или ссылке, а дополнительно — оценку Metacritic и примерное время прохождения с HowLongToBeat.
Затем уточнил: «делай всё по ТЗ, но плюс время с HLTB».

Документ [08](../08-import-providers.md) §2 прямо запрещает скрапинг HowLongToBeat, Metacritic
и SteamDB и предписывает брать время прохождения из IGDB. Исследование
[research/03](../research/03-external-apis.md) §A, §E п. 7 объясняет причины: публичного API нет
ни у одного из трёх, у SteamDB скрапинг карается автобаном, HLTB регулярно ломает неофициальные
обёртки и ведёт судебные споры со скраперами.

## Решение

Все три запроса пользователя выполняются, но через легальные точки входа.

| Запрос пользователя | Реализация |
|---|---|
| Данные из Steam по названию | `store.steampowered.com/api/storesearch` → `appdetails` |
| Данные по ссылке | из ссылки берётся идентификатор: `store.steampowered.com/app/<id>`, `steamcommunity.com/app/<id>`, `steam://store/<id>`, **`steamdb.info/app/<id>`**, голый appid, `igdb.com/games/<slug>` |
| Оценка Metacritic | `appdetails.metacritic.score` + `url` (единственный легальный источник) |
| Время прохождения «как на HLTB» | IGDB `game_time_to_beats`: `hastily` → «сюжет», `normally` → «с доп.», `completely` → «100 %» |

Ссылка на SteamDB принимается, но сам сайт не запрашивается: из неё извлекается `appid`,
и дальше работает API самого Steam.

## Дополнение: RAWG вместо IGDB там, где Twitch недоступен

Пользователь не смог завести приложение на dev.twitch.tv: Twitch требует двухфакторную
аутентификацию по номеру телефона и принимает не все страны. Обойти это нельзя — токен IGDB
выдаётся **только** через приложение Twitch (`client_credentials` на id.twitch.tv), другого
способа авторизации у IGDB нет, а раздавать чужие ключи запрещено их условиями.

Поэтому добавлен третий провайдер — **RAWG** (`rawg.io/apidocs`): ключ выдаётся сразу после
регистрации по электронной почте, ни телефона, ни двухфакторной аутентификации не нужно.
В документе 08 §2 он числился резервом («выключен по умолчанию») — теперь это рабочий источник.

| | IGDB | RAWG |
|---|---|---|
| Доступ | приложение Twitch, 2FA по телефону | ключ по регистрации на почту |
| Время прохождения | `game_time_to_beats`: сюжет / с побочными / на 100 % | `playtime`: одно усреднённое число часов → пишется в «сюжет» |
| Серия | `collections`/`franchises` | нет (`/game-series` возвращает игры без названия серии) |
| Обложка 600×900 | есть | нет, только горизонтальный фон |
| Лимит | 4 запроса в секунду | 20 000 запросов в месяц, некоммерческое использование, обязательна видимая ссылка на источник |

Оба остаются в списке: у кого приложение Twitch есть, IGDB даёт больше. При дополнении записи
Steam временем прохождения (`withPlaytime`) выбирается тот источник, который настроен, — сначала
IGDB, иначе RAWG. Теги RAWG размечены языком, поэтому при русском интерфейсе берутся русские.

## Дополнение: язык данных следует языку интерфейса

При русском интерфейсе Steam запрашивается дважды: `l=english` за структурой и `l=russian`
за текстами. Из русского ответа берутся только название, краткое описание и подробности;
жанры, категории и дата всегда читаются из английского — иначе рассыпается сопоставление
со справочниками по slug («Экшены», «Для одного игрока») и разбор даты («18 апр. 2011 г.»).
Локализованное название становится основным, оригинальное уходит в альтернативные:
«Ведьмак 3: Дикая Охота — Полное издание» + «The Witcher 3: Wild Hunt - Complete Edition».
Кавычки-ёлочки, в которые витрина оборачивает русские издания, снимаются.

Если перевода нет или второй запрос не прошёл, остаются английские тексты. У IGDB и RAWG
описания только английские — локализации у них нет.

## Что расходится с текстом документа 08

1. **Провайдеров три, а не семь.** Реализованы Steam (без ключей), RAWG и IGDB (ключи
   пользователя). SteamGridDB, Wikidata, OpenCritic и Steam Web API не реализованы; массового
   импорта библиотеки Steam (§3, «Массовый сценарий») нет.
2. **Кеш лежит в `data/providers/cache`, а не в `sync/cache`** (§4). Это локальные временные
   данные: им незачем попадать в бэкапы и на Google Диск, а `sync/` синхронизируется.
   Там же, в `data/providers/credentials.bin`, лежат зашифрованные `safeStorage` ключи IGDB.
3. **Связанные сущности приходят парой `{slug, name}`, а не только именем** (§3 п. 3). Каталог
   заполнен по-русски («Экшен», «Одиночная»), провайдеры отдают английские названия, поэтому
   сопоставление идёт по slug — он совпадает с английским термином. Таблица соответствий —
   `src/main/providers/taxonomy-map.ts`; платформы сопоставляются по имени (в `platforms`
   нет slug) и приводятся к точным именам каталога.
4. **Источники дополняют друг друга.** К записи IGDB добавляется оценка Metacritic из Steam
   (у IGDB её нет), к записи Steam — время прохождения из IGDB (Steam его не знает). Дополнение
   не обязательно: если второй источник не настроен или недоступен, карточка приходит без этих
   полей. Совпадение Steam → IGDB ищется по названию, поэтому оттуда берутся только время и
   серия — название, описание и картинки остаются Steam'овскими.
5. **Кнопки «Обновить из IGDB» на странице игры (§3 п. 5) нет.** Повторный импорт делается
   через ту же панель в форме редактирования; `raw_hash` в `external_ids` уже пишется, так что
   сравнение «есть ли новые данные» можно добавить позже без миграции.
6. **`field_provenance` заполняется по-новому.** Раньше при каждом сохранении все отслеживаемые
   поля помечались `manual, locked = 1`. Теперь поля, отмеченные пользователем в диалоге импорта,
   получают провайдера и `locked = 0` (импорт вправе их обновить), а остальные по-прежнему
   считаются ручным вводом и блокируются. Список отслеживаемых полей приведён к именам строк
   диалога импорта (`developers`/`publishers` вместо общего `companies`, добавлены `hltb`,
   `modes`, `tags`, `altTitles`, `releaseStatus`, `ageRating`, `website`).
7. **Возрастной рейтинг Steam — это `required_age`**, то есть «16+», а не PEGI/ESRB. Строковое
   поле `age_rating` это допускает; от IGDB приходит нормальный «PEGI Sixteen».

## Побочные исправления, найденные при проверке

- **Форма игры не сохранялась**, если поле «Номер в серии» (или любое другое необязательное
  числовое) оставалось пустым: `{ valueAsNumber: true }` превращает пустой `input[type=number]`
  в `NaN`, zod такое значение отвергает, и `handleSubmit` молча не вызывал обработчик —
  react-hook-form лишь переводил фокус на «пустое» поле. Введён `optionalNumber`
  (`src/renderer/src/lib/form-utils.ts`), который отдаёт `null`.
- Сообщение о незаполненном названии приходило от zod по-английски («Too small: expected
  string to have >=1 characters») — заменено локализованным `catalog.form.required`.

## Последствия

- Без ключей IGDB приложение полностью рабочее: Steam закрывает название, описание, студии,
  жанры, режимы, платформы, дату, возрастной ценз, сайт, Metacritic и три картинки. Не хватает
  только времени прохождения, серии, тем и альтернативных названий.
- Если IGDB когда-нибудь закроет `game_time_to_beats`, поля `hltb_*` остаются заполняемыми
  вручную — схема этого не запрещает.
