# ADR 0001 · Оболочка приложения: Electron 44, а не Tauri 2

Дата: 2026-09-07 · Статус: принято

## Контекст
Нужна переносимая Windows-оболочка для React-интерфейса с локальной SQLite, файловым хранилищем изображений и синхронизацией с Google Диском. Код будут писать модели-исполнители; у разработчика установлены Node 22 и npm, но нет Rust и MSVC Build Tools. Пользователь готов установить тулчейн, если это оправдано.

## Рассмотренные варианты
1. **Tauri 2** — exe ~15 МБ, WebView2, Rust-ядро. Требует Rust + MSVC (~7–10 ГБ); `tauri-plugin-sql` асинхронный, миграции в Rust, абсолютные пути к БД не подтверждены; официального OAuth-плагина и portable-таргета нет.
2. **Electron 44** — ~200 МБ, Chromium 152 + Node 24. better-sqlite3 13 поставляется с готовыми N-API-бинарниками (компилятор не нужен); `node:sqlite` как запасной вариант; синхронный SQLite API; electron-vite 5 активно поддерживается; таргет `dir` → zip даёт честный portable без распаковки во временную папку.

## Решение
Electron 44 + electron-vite 5 (Vite 7) + React 19 + TypeScript. Вся логика на TypeScript в main-процессе; сеть только в main; безопасность — sandbox, contextIsolation, CSP, fuses, кастомный протокол для картинок.

## Последствия
- Разработчику ничего дополнительно не устанавливать.
- Дистрибутив тяжелее (~200 МБ) и потребляет больше памяти; для личного приложения приемлемо.
- Нужно соблюдать security-чеклист Electron (документ 01 §8).
- Переход на Tauri возможен позже без изменения документов 02–10 (документ 01, приложение T).
