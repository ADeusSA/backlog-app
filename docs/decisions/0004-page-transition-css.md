# ADR 0004 · Переход между экранами — CSS-анимацией, а не motion

**Дата** 2026-09-08 · **Статус** принято · **Блок** 1.1

## Контекст

ТЗ 05 §4.4 требует при смене экрана cross-fade со сдвигом 12 px, а 04 §5 — брать длительности из
словаря движения. Первая реализация делала это через `motion`:

```tsx
<AnimatePresence mode="wait" initial={false}>
  <motion.div key={location.pathname} variants={variants.enter} initial="hidden" animate="visible" exit="exit">
    <Outlet />
  </motion.div>
</AnimatePresence>
```

После первой же смены экрана контентная область переставала отрисовываться: DOM был на месте
(проверено — заголовок 1122×166 в точке (72, 44), `opacity: 1`, `visibility: visible`,
`elementFromPoint` возвращал сам заголовок), но ни снимок экрана, ни `webContents.capturePage()`
не показывали ничего, кроме фона. Оболочка (titlebar, рельса) при этом рисовалась.

Причина — композиционный слой, который остаётся после JS-анимации `opacity`: внутри контента есть
элементы с `backdrop-filter` (панель фильтров, поповеры — класс `.glass`), и в Chromium 152
сочетание «анимируемая скриптом непрозрачность родителя + `backdrop-filter` у потомка» приводит к
тому, что поддерево перестаёт попадать в кадр. Отключение GPU (`--disable-gpu`) картину не меняло.

## Решение

Переход выполняет CSS-анимация `page-enter` (`globals.css`), а обёртка получает `key` по маршруту:

```tsx
<div key={location.pathname} className="page-enter h-full overflow-y-auto">
  <Outlet />
</div>
```

Длительность и кривая — те же токены `--d-page` / `--ease-emphasized`, что и в словаре движения,
так что визуально требование 05 §4.4 выполнено. CSS-анимация завершается, слой уничтожается,
контент рисуется нормально (проверено `capturePage`).

## Последствия

- Выход старого экрана не анимируется (при `mode="wait"` он и так был не виден): фактически это
  «появление» вместо «cross-fade». Отличие незаметно на 400 мс и не нарушает словарь движения.
- `prefers-reduced-motion` отключает анимацию отдельным медиа-запросом.
- Правило остаётся общим: **не анимировать `opacity` скриптом на контейнерах, внутри которых есть
  `backdrop-filter`**. Это же ограничение учитывать при shared-element переходе обложки (06 §6).
