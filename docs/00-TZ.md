# Backlog — техническое задание

**Версия** 1.0-draft · **Дата** 2026-09-07 · **Автор постановки** Barmin · **Составитель** Claude (анализ, архитектура, дизайн-система) · **Исполнители** — модели-кодогенераторы по правилам документа 10 §3.

Это индексный документ. Он определяет назначение продукта, границы, термины и связывает исходные требования с тематическими документами, где они раскрыты до уровня, достаточного для реализации без дополнительных вопросов.

## 1. Назначение

Переносимое Windows-приложение для ведения личного бэклога видеоигр — аналог Backloggd / Letterboxd / Shikimori, но локальное: данные лежат в папке приложения (SQLite + изображения) и синхронизируются с личным Google Диском пользователя. Один пользователь, несколько ПК, без сервера и аккаунтов, кроме Google для хранения.

Ценность для пользователя: видеть, что хочу пройти, что прохожу и что пройдено; вести списки, серии, студии; фиксировать время и оценки; получать красивую статистику. Приложение должно быть приятным ежедневным инструментом: быстрым, анимированным, с продуманным дизайном (выбрана система «Aurora», документ 04).

## 2. Термины

| Термин | Значение |
|---|---|
| **Каталог** | Объективные данные о мире игр: игры, компании (студии/издатели), серии, жанры, платформы, режимы, изображения. Создаются вручную (итерация 1) или импортом (итерация 3). |
| **Библиотека** | Игры, с которыми у пользователя есть отношение (`user_game`): статус, оценка, время, заметки. Игра в каталоге ≠ игра в библиотеке. |
| **Статус** | Один из семи взаимоисключающих: Хочу · Бэклог · Играю · Пройдена · Отложена · Брошена · Поиграл. |
| **Бэклог** | В узком смысле — статус «Бэклог»; в широком (название приложения) — вся библиотека. В UI «Бэклог» — пункт меню статуса, «Библиотека → Все» — всё. |
| **Список** | Пользовательская подборка игр с ручным порядком, обложкой, описанием. Число списков не ограничено. |
| **Серия** | Франшиза/коллекция игр с нумерацией (Call of Duty, Metro). Может иметь под-серии. |
| **Компания** | Студия-разработчик и/или издатель — одна сущность с флагами ролей и связью «родитель» (Bethesda → ZeniMax → Xbox). |
| **Коллекция игр** | Единый UI-компонент: сетка/список карточек + панель фильтров + сортировка + кольцо прогресса. Используется во всех списковых экранах. |
| **Кольцо прогресса** | Круговой индикатор «пройдено / всего» с процентом. |
| **Модерация** | Экран добавления и редактирования каталога (название из постановки; приложение однопользовательское, «модерация» = редактор контента). |
| **Ревизия БД** | Счётчик в `meta.db_revision`, растёт при каждой записи; основа синхронизации. |
| **Scope** | Контекст коллекции: библиотека/статус, список, серия, компания, поиск, каталог. |

## 3. Пользователь и ключевые сценарии

Единственный пользователь — владелец ПК (возможно, нескольких). Сценарии по частоте:
1. Открыл приложение → увидел «Сейчас играю» → записал время / сменил статус.
2. Купил или захотел игру → нашёл в каталоге или создал → добавил в бэклог с приоритетом.
3. Прошёл игру → статус «Пройдена», оценка, отзыв → кольца и статистика обновились.
4. Составил список («Cozy игры») → упорядочил перетаскиванием → добавил из фильтра «все RPG 2015–2020».
5. Заполнил серию → пронумеровал → смотрит прогресс по серии и по студии.
6. Пересел на другой ПК → база подтянулась из Google Диска.
7. Ищет, что поиграть → фильтры (≤ 15 ч, жанр, платформа) или кнопка «Случайная».

## 4. Границы

**Делаем (итерация 1):** всё из §5 со статусом MVP; ручной ввод контента; синхронизация Google Диска; portable-сборка Windows.
**Не делаем в итерации 1, но закладываем:** импорт из IGDB/Steam (08), журнал сессий/несколько прохождений/итоги года (10 §1), светлая тема (04 §8). Достижения и уровни (09) — **в итерации 1** (решение пользователя 2026-09-07).
**Не делаем вообще:** соцсеть, публичные профили, мультиаккаунт, мобильные версии, запуск игр (это не лаунчер), DRM/магазины.

## 9. Ключевые решения (сводка)

- **Данные**: один файл SQLite + папка WebP-изображений; UUID v7; 7 статусов; оценка 1–10 (5 звёзд с половинками); каталог отделён от пользовательских данных; tombstones и ревизия для синхронизации; FTS5 для поиска.
- **Синхронизация**: файловая (снимок БД + картинки) в личный Google Диск, pull при старте, push отложенно и при выходе, конфликт = выбор пользователя, история версий в облаке. **Для конечного пользователя — ноль настроек**: одна кнопка «Войти через Google» при первом запуске; OAuth-клиент вшит в сборку и настраивается владельцем один раз (03 §11). Приложение можно передать другому человеку как есть. Детали — 03.
- **Дизайн**: Aurora, dark-only в итерации 1; один акцент; подкраска карточек статусом ≤ 18 %; стекло ≤ 5 элементов; словарь движения.
- **Навигация**: сайдбар-рельса + история браузерного типа + крошки с выпадающими «соседями» + `Ctrl+K`.
- **Геймификация**: уровни и достижения — в итерации 1 (09); **импорт** из внешних источников — задел в схеме и UI, реализация в итерации 3 (08).
- **Владение**: значения Цифра / Физическая / Подписка / **Пиратка** / Нет / Продана (решение пользователя: «пиратка» — это владение, а не платформа; платформы остаются PC / PS / Xbox / …), см. 02 §3.8.
- **Стек**: Electron 44 + electron-vite 5 (Vite 7) + React 19 + TypeScript 5.9 + Tailwind 4 + shadcn/ui + motion + TanStack; better-sqlite3 13 в main-процессе (prebuilt, без компилятора); zero-dependency OAuth/Drive на `fetch`; portable = zip папки `win-unpacked`. Разработчику ничего ставить не нужно (Node 22 уже есть). Обоснование и приложение про Tauri — документ 01.
